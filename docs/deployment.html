Systemd & Containers

Fluxheim ships with a hardened systemd unit, RPM packaging, and rootless Podman container images for Wolfi, Alpine, SUSE Micro, and Debian.

Systemd Deployment

The tarball includes a pre-configured hardened systemd unit. The unit runs Fluxheim with CAP_NET_BIND_SERVICE (to allow ports 80/443 without root) and a dedicated system user.

Setup

bash — systemd setup
# 1. Install the binary and unit file
sudo mv fluxheim /usr/local/bin/
sudo mv fluxheim-acme /usr/local/bin/
sudo cp packaging/systemd/fluxheim.service /etc/systemd/system/

# 2. Create the system user
sudo useradd -r -s /sbin/nologin -d /var/lib/fluxheim fluxheim

# 3. Create required directories and set ownership
sudo mkdir -p /etc/fluxheim /srv/fluxheim /var/log/fluxheim \
              /var/cache/fluxheim /var/lib/fluxheim/acme
sudo chown -R fluxheim:fluxheim /srv/fluxheim /var/log/fluxheim \
              /var/cache/fluxheim /var/lib/fluxheim

# 4. Place your config
sudo cp /path/to/your/fluxheim.toml /etc/fluxheim/fluxheim.toml

# 5. Validate config as the fluxheim user
sudo -u fluxheim fluxheim --check-config --config /etc/fluxheim/fluxheim.toml

# 6. Enable and start
sudo systemctl daemon-reload
sudo systemctl enable --now fluxheim

# 7. Verify
sudo systemctl status fluxheim
sudo journalctl -u fluxheim -f

Config Reload

Fluxheim supports live config reload without dropping connections. Send SIGHUP or use the admin API.

bash
# Via systemd (sends SIGHUP)
sudo systemctl reload fluxheim

# Or via admin API
curl -X POST http://127.0.0.1:9090/_fluxheim/reload \
  -H "Authorization: Bearer $ADMIN_TOKEN"

Rootless Podman Containers

Fluxheim's official container images are designed for rootless Podman operation. They use internal ports 8080 (HTTP) and 8443 (HTTPS) by default — no root required. The same release image set is published to GHCR and Quay at quay.io/valkyoth/fluxheim.

Podman Quadlet (systemd integration)

Use Podman Quadlet to manage container lifecycle with systemd on the host:

~/.config/containers/systemd/fluxheim.container
[Unit]
Description=Fluxheim Edge Server
After=network-online.target

[Container]
Image=ghcr.io/valkyoth/fluxheim:v1.6.28
PublishPort=8080:8080
PublishPort=8443:8443
Volume=/srv/sites:/srv/sites:ro,z
Volume=/etc/fluxheim:/etc/fluxheim:ro,z
Volume=/var/lib/fluxheim/acme:/var/lib/fluxheim/acme:rw,z
AutoUpdate=registry

[Service]
Restart=always

[Install]
WantedBy=default.target

Production Readiness Checklist

  • Run fluxheim --check-config before every restart or reload
  • Run scripts/release_checks.sh before publishing security-sensitive changes
  • Pin to a specific image digest in production, not latest
  • Mount config and site content as read-only (:ro)
  • Mount ACME state directory as read-write (:rw) separately
  • Use the admin API over loopback only, or configure a trusted TLS terminator
  • Set [server.host_routing] strict = true for multi-tenant hardened deployments
  • Review deny_dotfiles = true is set on all [vhosts.web] sections
  • Verify HSTS is only set when TLS is confirmed working

The native systemd unit (at packaging/default/fluxheim.toml) listens on ports 80 and 443 with CAP_NET_BIND_SERVICE. Container configs (at packaging/container/fluxheim.toml) use internal ports 8080 and 8443 for rootless compatibility.
