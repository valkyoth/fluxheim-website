Fluxheim Docs TLS & ACME

TLS & ACME

Fluxheim ships with rustls as the default TLS backend and full managed ACME support for automatic certificate issuance and renewal.

TLS Backends

TLS backends are compile-time selections. Exactly one backend must be chosen when TLS is needed. Selecting more than one is a compile error.

FeatureStatusNotes
tls-rustlsDefault & RecommendedMemory-safe Rust TLS. Multi-cert SNI. Used in all official builds.
tls-opensslOptionalOpenSSL backend. FIPS-capable deployments.
tls-boringsslOptionalBoringSSL backend. FIPS-140-3 compliance path.
tls-s2nOptionals2n-tls backend. AWS-backed TLS implementation.

Static / Bought Certificates

Configure a certificate and key file path per vhost. rustls supports multi-cert SNI — you can configure multiple vhosts each with their own certificate.

fluxheim.toml — static cert
[server]
tls_listen = ["0.0.0.0:443"]

[[vhosts]]
name = "site"
hosts = ["example.com"]

[vhosts.tls]
enabled = true

[vhosts.tls.certificate]
cert_path = "/etc/fluxheim/certs/example.com.pem"
key_path = "/etc/fluxheim/certs/example.com.key"

Managed ACME — Auto-Issuance

Enable global ACME storage and then enable ACME on each vhost that should receive managed certificates. Requires the acme-client Cargo feature for live issuance and renewal.

fluxheim.toml — managed ACME
[server]
listen = ["0.0.0.0:80"]
tls_listen = ["0.0.0.0:443"]

[tls.acme]
enabled = true
storage = "/var/lib/fluxheim/acme"
contact_email = "admin@example.com"
default_issuer = "letsencrypt"
challenge = "http-01"

[[vhosts]]
name = "site"
hosts = ["example.com", "www.example.com"]

[vhosts.tls]
enabled = true

[vhosts.tls.acme]
enabled = true
# issuer = "letsencrypt"
# domains = ["example.com", "www.example.com"]

ACME Challenge Methods

  • HTTP-01 — Port 80 must be reachable from the internet. Fluxheim handles the challenge automatically.
  • TLS-ALPN-01 — Requires the tls-rustls backend and port 443 to be reachable. No HTTP dependency.

acme-init — Guided Bootstrap

Packaged 1.3.x builds include acme-init for guided issuer bootstrap before the first run.

bash
# Bootstrap with Let's Encrypt
sudo fluxheim acme-init letsencrypt

# Bootstrap with Actalis (free, EAB-capable)
sudo fluxheim acme-init actalis

# After acme-init, start Fluxheim — certificates are issued on first request
sudo systemctl start fluxheim

External ACME with fluxheim-acme

The companion tool fluxheim-acme (included in release builds from v1.3.2) handles renewal, status checks, and graceful reload for service-manager and container deployments where certificates are managed externally.

bash
fluxheim-acme status          # check certificate status
fluxheim-acme renew           # trigger renewal if due
fluxheim-acme renew --vhost site
fluxheim-acme reload          # signal Fluxheim to reload certs

EAB — External Account Binding

Some ACME CAs (such as Actalis) require External Account Binding credentials. Configure EAB in the ACME issuer section.

fluxheim.toml — EAB issuer
[[tls.acme.issuers]]
name = "actalis"
directory_url = "https://acme-api.actalis.com/acme/directory"

[tls.acme.issuers.eab]
key_id_credential = "actalis-eab-kid"
hmac_key_credential = "actalis-eab-hmac-key"

See examples/acme-actalis.toml in the repository for a complete working example.

TLS Policy Profiles

Fluxheim supports two TLS policy profiles that control cipher suite and protocol version selection:

  • modern — TLS 1.3 only. Strongest security. May not support very old clients.
  • intermediate — TLS 1.2 + 1.3. Broader client compatibility. Follows Mozilla intermediate guidelines.

See examples/tls-modern.toml and examples/tls-intermediate.toml in the repository for checked policy examples.

Important: Set strict_transport_security in [headers.response] only when TLS is configured and working. An incorrect HSTS header on an HTTP-only host can make it unreachable.
