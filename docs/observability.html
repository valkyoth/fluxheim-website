Fluxheim Docs Observability

Observability

Fluxheim supports Prometheus metrics, OpenTelemetry metrics and traces, and structured logging. All observability features are opt-in at compile time.

Prometheus
Requires metrics feature
OTLP Metrics
Requires metrics-otlp
OTLP Tracing
Requires otel-tracing + otel-otlp

Building with Observability

bash
# Full observability profile
cargo build --release --no-default-features \
  --features profile-observability

# Or manually add to any profile
cargo build --release --no-default-features \
  --features profile-core,metrics,metrics-otlp,otel-tracing,otel-otlp

The official full release binary includes all observability features. The cache and proxy edge binaries do not include metrics or tracing by default.

Prometheus Metrics

Enable a Prometheus-compatible /metrics scrape endpoint by configuring the metrics listener.

fluxheim.toml
[metrics]
enabled = true
listen = "127.0.0.1:9091"
require_loopback = true

Scraping with Prometheus

prometheus.yml
scrape_configs:
  - job_name: fluxheim
    static_configs:
      - targets: ['127.0.0.1:9091']
    scrape_interval: 15s

Available Metrics

  • fluxheim_acme_events_total{event} — bounded ACME lifecycle outcomes
  • fluxheim_cache_activity_total{tier,event} — aggregate cache hit, miss, store, purge, stale, and peer-fill activity
  • fluxheim_cache_activity_scope_total{scope,vhost,route,tier,event} — configured vhost/route cache activity without raw host or path labels
  • fluxheim_cache_operation_duration_seconds{scope,vhost,route,phase,operation} — cache lookup and request-collapsing wait durations
  • fluxheim_cache_purger_runs_total{outcome} and related purger metrics — cache cleanup health
  • fluxheim_metrics_otlp_exports_total{outcome} — OTLP metrics exporter health

OpenTelemetry Metrics (OTLP)

Requires the metrics-otlp Cargo feature. Exports metrics to an OTLP-compatible endpoint (Grafana Alloy, OpenTelemetry Collector, etc.).

fluxheim.toml
[metrics.otlp]
enabled = true
endpoint = "http://127.0.0.1:9090/api/v1/otlp/v1/metrics"
service_name = "fluxheim"
interval_secs = 15
timeout_secs = 2

OpenTelemetry Tracing

Requires otel-tracing for trace context propagation and otel-otlp for exporting traces. Propagates W3C traceparent headers to upstream services.

fluxheim.toml
[tracing]
enabled = true
mode = "propagate_only"
traceparent = true
log_trace_id = true

[tracing.otlp]
enabled = true
endpoint = "http://127.0.0.1:4318/v1/traces"
service_name = "fluxheim"
queue_size = 8192
timeout_secs = 2

What gets traced

  • Inbound W3C traceparent validation and normalized propagation to upstreams
  • Structured access-log trace IDs when log_trace_id is enabled
  • Bounded request spans for OTLP export when tracing.otlp.enabled is true
  • Cache attributes for cache-phase timing when the binary includes the cache feature

Logging

Fluxheim emits structured logs. Log level, format, target, and access-log fields are controlled by the [logging] config.

bash
[logging]
level = "info"
format = "json"
target = "stderr"

[logging.access]
enabled = true
include_host = true
include_path = true
request_id = true

profile-observability Build

The profile-observability alias enables the full observability stack on top of profile-core: Prometheus metrics listener, OTLP metrics export, trace context propagation, and OTLP trace export.

bash
cargo build --release --no-default-features \
  --features profile-observability,acme-client
