Fluxheim Docs Installation & Quick Start

Installation & Quick Start

Get Fluxheim running in under five minutes — from tarball, container, or source.

Prerequisites

  • Linux x86_64 (kernel 4.14 or newer)
  • For source builds: Rust stable toolchain (pinned — use rustup)
  • For containers: Podman 4+ (rootless) or Docker

Option 1 — Tarball (Recommended)

The tarball is the fastest way to get started. Download the pre-built binary, move it to your PATH, and you're ready.

1

Download the tarball

bash
curl -L https://github.com/valkyoth/fluxheim/releases/download/v1.4.3/fluxheim-1.4.3-full-x86_64-linux.tar.gz \
  -o fluxheim-1.4.3.tar.gz
tar xzf fluxheim-1.4.3.tar.gz
2

Move binaries to your path

bash
sudo mv fluxheim /usr/local/bin/
sudo mv fluxheim-acme /usr/local/bin/            # ACME companion
sudo mv fluxheim-config-tester /usr/local/bin/   # Config validator
fluxheim --version
3

Create a minimal config and validate it

bash
sudo mkdir -p /etc/fluxheim /srv/sites/example/public
echo '<h1>Hello from Fluxheim</h1>' | sudo tee /srv/sites/example/public/index.html
fluxheim --check-config --config /etc/fluxheim/fluxheim.toml
4

Run it

bash
sudo fluxheim --config /etc/fluxheim/fluxheim.toml

# Test with curl
curl -H 'Host: localhost' http://127.0.0.1:8080/

Option 2 — Container (Rootless Podman)

bash
# Pull the full image
podman pull ghcr.io/valkyoth/fluxheim:1.4.3

# Run rootless — ports 8080 (HTTP) and 8443 (HTTPS)
podman run -d \
  --name fluxheim \
  --restart unless-stopped \
  -p 8080:8080 \
  -p 8443:8443 \
  -v /srv/sites:/srv/sites:ro,z \
  -v /etc/fluxheim:/etc/fluxheim:ro,z \
  ghcr.io/valkyoth/fluxheim:1.4.3

podman logs -f fluxheim

Option 3 — Build from Source

bash
git clone https://github.com/valkyoth/fluxheim
cd fluxheim

# Default profile: proxy + web + cache + tls-rustls + security
cargo build --release

# Validate and run
./target/release/fluxheim --check-config --config examples/fluxheim.toml
./target/release/fluxheim --config examples/fluxheim.toml

# Run local checks
scripts/checks.sh

Your First Config

A minimal static site config. Save this to /etc/fluxheim/fluxheim.toml.

/etc/fluxheim/fluxheim.toml
[server]
listen = ["0.0.0.0:8080"]
default_vhost = "site"

[headers.response]
enabled = true
x_content_type_options = "nosniff"
x_frame_options = "DENY"
referrer_policy = "no-referrer"

[[vhosts]]
name = "site"
hosts = ["example.test", "www.example.test"]

[vhosts.web]
root = "/srv/sites/example/public"
index_files = ["index.html"]
deny_dotfiles = true
cache_control = "public, max-age=60"

Adding a Reverse Proxy Route

fluxheim.toml — proxy route
[[vhosts]]
name = "app"
hosts = ["app.example.com"]

# Route /api/* to a backend
[[vhosts.routes]]
name = "api"
path_prefix = "/api"
[vhosts.routes.proxy]
upstreams = ["127.0.0.1:3000"]

# Serve static assets from disk
[[vhosts.routes]]
name = "static"
path_prefix = "/"
[vhosts.routes.web]
root = "/srv/sites/app/public"
index_files = ["index.html"]

[vhosts.web]
root = "/srv/sites/app/public"
index_files = ["index.html"]

Build Profiles

Fluxheim uses Cargo feature aliases called profile-* for grouped builds. Choose the profile that matches your deployment role.

Profile Use case
profile-coreDefault local/server baseline
profile-static-siteStatic sites without Fluxheim cache
profile-reverse-proxyReverse proxy without static hosting or cache
profile-cache-serverStatic/proxy server with cache enabled
profile-cache-edgeCache edge without local static web serving
profile-proxy-edgeFocused reverse proxy edge
profile-load-balancerProduction proxy/load-balancer bundle with compression enabled
profile-load-balancer-edgeLoad-balancer edge without cache or static web
profile-observabilityCore server with full metrics and tracing
profile-privacyZero-retention static/proxy profile
profile-web-serverStatic webserver profile
profile-fullAll stable production modules, including traffic mirroring
profile-developmentBroad development build with compatible production modules
bash — build a focused profile
# Cache edge with managed ACME
cargo build --release --no-default-features \
  --features profile-cache-edge,acme-client

# Proxy edge
cargo build --release --no-default-features \
  --features profile-proxy-edge,acme-client

# Full production build
cargo build --release --no-default-features \
  --features profile-full,acme-client,metrics,metrics-otlp,otel-tracing,otel-otlp

# PHP-FPM build
cargo build --release --no-default-features \
  --features profile-web-server,php-fpm,acme-client

Validate custom features before building — scripts/validate-features.sh proxy,web,tls-rustls checks that the selected feature combination is coherent. TLS backends are mutually exclusive; pick exactly one.
